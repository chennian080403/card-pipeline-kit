# 自审与验收

## 谁能批准

| 角色 | 能做 | 不能做 |
|---|---|---|
| AI / 流水线 | 上传、生成、拼图、写 review、记 feedback、登记**草稿** | 批准、定稿、覆盖冻结母版、删除历史 |
| 人 | 审核页点「要 / 不要 / 定为真源」，素材库点定稿 | —— |

`register` 送出的 `production_approved` 恒为 `false`。**只有人**在素材库里点定稿。

## 自动可判的项（AI 逐张看图后记结论）

- **尺寸与格式**：`sniff_image` 读实际字节，`width/height/has_alpha` 记进 manifest 与 review。**不信文件后缀**，也不信"看起来像透明"的棋盘格预览。
- **透明**：`transparent: true` 的卡，`has_alpha` 必须为真且确有像素 alpha < 255。画进 RGB 图的棋盘格不是透明。
- **参考图是否真的带上了**：`ref_count` 与 `ref_missing` 都记录在案；缺的写清是"没登记"还是"文件不在"。
- **字数**：`compose` 报字数并给 warn/reject；超 reject 拒提交（`--force` 才发）。

## 需要人/模型看图判断的项（写进 review 的 `--note`）

通用清单（卡里 `checklist` 可加项）：

1. **身份**：脸、体型、发型是否与真源一致（lean 卡主要靠参考图，最容易在这里翻车）。
2. **道具**：数量、朝向、握持方式对不对（多一只手、多一只耳坠是典型失败）。
3. **构图**：谁在左谁在右、朝向、视线、留白是否符合 `composition`。
4. **多余物**：画面里有没有不该有的字、水印、logo、签名。
5. **残留**：素材抠图类要求没有棋盘格/底噪残留（半透明纱里抠不掉的格子是已知边界）。
6. **表情与情绪**：是否符合 `expression` 与 `action`。

## 结论

人在审核页只给两种：「要」（= `keep`：pass + pick + 登记草稿）和「不要」（= `review … fail`）。拿不准就不点，图留在出图区。

主模型自审用命令行 `review <卡> <候选> pass|fail|borderline --note "…"`（默认 `--by claude`）：`borderline` 只表示「拿不准、请人看」，页面上仍留在出图区（标「旧·待定」）。`fail` 原因可不写；写了就进 `feedback`，是下一轮改卡的依据。主模型自审给 `fail` 时仍应写原因，方便归因。

主模型只提议 1~2 张「建议要」给人，不要把所有候选一起倒过去，也不替人点「要」。

## 批预算与确认

- `generate` 必须带 `--approved "<谁/何时>"`，记进 manifest 的 `approvals`。
- `--budget` 是**总张数**，不是增量；`ok` 幂等跳过，重跑不会多花钱。
- 首生优于修图：默认不改图，不满意**改卡重生**（而不是在旧图上反复修），所以每次 `generate` 都按新序号出新候选，旧的留档。

## 反馈归因

```bash
$PL feedback 05-01 reject --reason "顾挽多了一只耳坠" --root-cause "lean 卡没带 face 参考"
```

归因决定下一步：`改卡`（构图/动作/表情）还是 `改真源`（长相）还是 `改口径块`（风格/禁令）。**别用改提示词的方式掩盖真源问题**——真源一改，所有卡一起好。
